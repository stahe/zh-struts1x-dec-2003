## 目标

本项目的目标是探索 **Struts 1.x** 开发框架，该框架源于 **Apache 软件基金会** 的 Jakarta Struts 项目。

Struts 为基于 **MVC（模型-视图-控制器）** 架构模型的 Java Web 应用程序开发提供了一个标准框架。

教学目标包括：

* 理解 MVC 模型的原则
* 正确构建 Java Web 应用程序的结构
* 明确分离展示层、业务逻辑层和数据访问层
* 使用 Servlet 和 JSP 实现该架构

## MVC 模型
**MVC（模型–视图–控制器）** 模型旨在分离：
| 层级             | 作用                  |
| ------------------ | --------------------- |
| **视图 (V)**        | 用户界面 |
| **控制器 (C)** | 业务逻辑   |
| **模型 (M)**     | 数据访问     |

该架构也被称为 **三层架构**。

### 1️⃣ 视图 – 用户界面

* 通常为网页浏览器
* 也可以是独立应用程序
* 发送 HTTP 请求并格式化结果

### 2️⃣ 控制器 – 应用逻辑

* 处理用户请求
* 协调处理活动
* 调用业务类和数据源

### 3️⃣ 模型 – 数据源

可包含：
*
* 数据库
* 平面文件
* Web 服务
* LDAP 目录
* 任何其他持久化数据源
*
* MVC 模型的主要目标是保持这三个层级之间的**高度独立性**，以限制变更的影响。

## 基于 Servlet 和 JSP 的 MVC 架构

当使用传统的 Java EE 技术（Servlet + JSP）实现 MVC 时，其架构组织如下：

### 🔹 控制器 (Controller)
* 一个 **Servlet** 作为应用程序的入口点
* 集中处理 HTTP 请求

### 🔹 业务逻辑
* 一组 **业务类**
* 实现业务规则

### 🔹 数据访问
* **数据访问类 (DAO)**
* 与数据库或其他系统交互

### 🔹 视图

* **JSP** 页面
* 负责呈现

---

## 为什么选择 Struts？

Struts 通过以下方式规范了这种组织结构：

* 集中化请求控制
* 标准化操作管理
* 促进任务分离
* 以工业级标准构建 Java Web 应用程序

因此，它为开发严格遵循 MVC 架构的 Web 应用程序提供了一个坚实的框架。
